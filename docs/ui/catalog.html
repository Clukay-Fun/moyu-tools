动效

下面每张卡片都在自动循环播放应用里的真实动效（用的是应用本身的类名和过渡，不是另画的动画）。动效只服务于反馈：按下有回弹、浮层有出现、状态切换有滑动。时长与缓动一律取变量。

时长
按用途命名，同用途才共用：--dur-hover 悬停的颜色/背景/边框 · --dur-press 按下与开关 · --dur-popover 浮层入场 · --dur-popover-exit 浮层退场 · --dur-panel 面板（轻提示、图片编辑面板）。取值不同的旧写法（进度条 160ms、拖放高亮 150ms 等）保持原值，不为统一改变节奏
缓动
--ease-out——出现和位移；颜色、背景这类非位移变化用 ease；两个位置之间来回滑（分段指示器）现在用的是 cubic-bezier(0.77, 0, 0.175, 1)，还没有变量
减弱动效
系统开启「减少动态效果」时，全局兜底只保留颜色/透明度过渡，位移、缩放、按下回弹一律不动（style.css「减弱动效兜底」）

按下回弹

scale(var(--press-scale))（0.97）· --dur-press · --ease-out

图片编辑器内的工具按钮、对象按钮、色块保留各自取值（0.96 / 0.94 / 0.9）

悬停反馈

颜色 / 背景 / 边框 · --dur-hover · ease

画布命令菜单项是 110ms，比 --dur-hover 快，保持原值

浮层开合

入场 opacity + translateY(-2px) + scale(0.98) · --dur-popover

退场 .closing 淡出 · --dur-popover-exit（120ms），结束后才设 hidden；淡出途中可被重新打开

滑动指示器

左侧子菜单同类指示器用 220ms——两处时长不一致

下拉菜单

原生 <select> 的弹层由系统绘制，透明度、圆角、模糊都控制不了，压在画布上会露底。应用里的下拉统一由 enhanceSelect() 增强成自绘触发器 + 菜单；命令菜单直接用 .app-menu。菜单挂在 #overlay-layer，由 placePopover() 定位，不会被滚动容器裁掉。

选择下拉
.app-select-trigger + .app-menu.app-select-menu；选中项 aria-selected="true"（主题色填充），不可选项 disabled
命令菜单
.app-menu + button；可勾选项用 aria-checked="true"（右侧 ✓）
写法
业务里仍写原生 <select>，调用 enhanceSelect(select) 即可；不要自己再拼一套

使用约定

颜色、字号、圆角、间距从变量取；需要新值时先加变量，再在这里补示例。

浅色模式下 --border / --control-border 是白色半透明，放在浅底上几乎看不见——需要可见描边时用 color-mix(in srgb, var(--foreground) 13%, transparent)。这一条是第一批统一的候选：给中性灰描边单独立一个变量。

键盘焦点统一为「实线内圈 + 柔光」（--focus-ring-color / --focus-glow），只在 Tab 操作时出现；焦点样式里不要改 border-radius，outline 与 box-shadow 本身会跟随控件圆角；新增的可交互控件如果真实的 input 被隐藏了，要把焦点环画到可见的替身上（参考开关）。

目录建成时顺手修掉的：深色模式下 .gbtn.primary 丢失主题色填充（一条多余的 [data-theme="dark"] .gbtn 规则特异性更高）；开关禁用态与可用态看不出区别。

刀模画布、图片编辑器、截图覆盖层有各自的交互约束，不为了统一去改它们已验收的样式。

盘点现状：node scripts/style-report.mjs（加 --json 输出机器可读结果）。
